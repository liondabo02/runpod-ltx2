# Q99-037 — Katı teslimat kapısı + üç görevlik sandbox denemesi

**Tarih:** 2026-10-22 · **Kapsam:** yalnız kodlama işçisinin teslim kalitesi
**Kısıtlar:** Oracle/bulut hesabına dokunulmadı, ücretli model yok, kaynak/kota
sınırları genişletilmedi, eşzamanlı yazma yapılmadı (`project_qa.py` başka ajan
tarafından yazıldığı için değiştirilmedi).

## Kural (kod)

`AutonomyRunner.delivery_verdict()` — bir görev ancak şu İKİ koşulla teslimdir:

1. **Gerçek dosya değişikliği**: işçi özetindeki `N dosya değişti` sayısı > 0.
   `0` ise veya işçi sayı bildirmediyse görev **failed** yazılır, `executed` artmaz.
2. **Bağımsız kabul**: projenin kendi kapısı (`tools/check_offline.py`) ayrıca
   çalıştırılır ve `exit 0` döner. Tarayıcı açılışı kabul sayılmaz; kapısı olmayan
   proje "doğrulanmış teslimat" iddia edemez.

`AHOS_REQUIRE_ACCEPTANCE=0` yalnız açıkça verilirse kabul koşulu kapanır.

## Testler (izole, canlı projeye dokunmaz)

```
python -m pytest -q tests/test_delivery_verdict.py     → 7 passed
python -m pytest -q                                    → 653 passed, 3 kırık (diğer ajan WIP)
```

Pozitif/negatif kapsam:

| Test | Beklenen |
|---|---|
| 2 dosya değişti + kapı geçti | ✅ teslim |
| 0 dosya değişti | ❌ "teslimat yok" |
| 3 dosya değişti + kapı düştü | ❌ "kabul kapısı düştü" |
| 1 dosya değişti, kapı yok ("tarayıcı geçti") | ❌ "kabul kapısı yok" |
| işçi değişiklik sayısı bildirmedi | ❌ |
| `AHOS_REQUIRE_ACCEPTANCE=0` | ✅ (bilinçli istisna) |
| `run_once` sıfır değişiklikle routed | ❌ `failed=1, executed=0` |

## Üç görevlik sandbox denemesi

`quality/tools/sandbox_trial.py` — Mipiluna geçici kopyaya alınır, işçi orada koşar,
karar gerçek diff + kabul kapısıyla verilir.

```
[RED] 3.2s · günün ipucu şeridi       · 0 dosya · kabul=geçti
[RED] 4.4s · tam ekran düğmesi        · 0 dosya · kabul=geçti
[RED] 3.3s · renk koru modu           · 0 dosya · kabul=geçti

teslim: 0/3 · sıfır değişiklikle 'başarılı' görünen: 0
```

Neden: ücretsiz uçların tamamı **HTTP 429** döndü (4 model, her biri bir kez
denendi — sınırlı fallback). İşçi sahte başarı üretmedi; kapı bunu doğru şekilde
RED olarak raporladı. Ham kayıt: `quality/evidence/sandbox-trial.json`.

## Pozitif kontrol nereden geliyor

- Birim testleri: sahte işçi sonucu + gerçek `check_offline` kapısı → teslim.
- Önceki canlı ölçüm (kota açıkken): 2/2 görev, 1'er dosya, kabul geçti
  (`quality/evidence/Q99-036.md`).

Yani pozitif yol kanıtlı; bugünkü 0/3 sonucu model kotasının tükenmesidir,
kapının sahte başarıya izin vermemesidir.
