# Q99-027 — Kanıt duraklaması artık kalıcı değil (geri çekilme + yeniden deneme)

**Tarih:** 2026-10-21 · **Durum:** kod + canlı daemon güncellendi

## Sorun

Kanıt kapısı üst üste 3 "0 dosya" görevinde `autonomy.pause` yazıyor ve döngü
**sonsuza kadar** duruyordu. Deterministik katalog Mipiluna'da tükendiği için bu,
"her zaman açık" hedefiyle çelişiyor: projeler değişse bile (başka ajan düzenler,
yeni gün yeni iş) sistem bir daha denemiyordu.

## Çözüm

`daemon.py` — `pause_cooldown_minutes` (varsayılan **120 dk**):

- Her tick'te `autonomy.pause` dosyasının yaşına bakılır,
- yaş eşiği geçtiyse dosya silinir, `no_evidence_streak=0` yapılır ve döngü
  yeniden dener,
- yine 3 no-op olursa yeniden duraklar (sahte ilerleme yine engellenir),
- `0` verilerek kapatılabilir.

CLI: `--pause-cooldown-minutes`; PowerShell: `-PauseCooldownMinutes` (varsayılan 120).

## Testler

```
python -m pytest -q tests/test_daemon.py
28 passed
```

Yeni: eski duraklama silinir + sayaç sıfırlanır; taze duraklama korunur;
kapatıldığında (0) hiç dokunulmaz.

## Canlı doğrulama

Manuel olarak mevcut `autonomy.pause` kaldırıldı, daemon yeniden başladı:

```
daemon pid=16944 ticks=1 status=idle streak=0
pause=False
```

## Kalan risk

- 2 saatlik yeniden deneme, model olmadan yine no-op üretip duracak; bu beklenen
  ve dürüst davranış. Asıl sıçrama model bağlandığında olacak.
- Cooldown süresi sabit; iş yoğunluğuna göre ayarlanabilir.
